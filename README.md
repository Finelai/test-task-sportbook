# Мини-спортсбук

Реализованы два сервиса на Go и PostgreSQL. Line публикует линию и выдаёт предложения с фиксированным коэффициентом. Wallet ведёт баланс и резервы одного игрока. HTTP-маршруты ставок возвращают примеры из контрактной заглушки. Веб-приложение на Vue 3 и TypeScript пока содержит стартовый экран.

## Запуск

Из корня репозитория запустите Docker Compose с профилем `wallet-check`. Для проверки нужны свободные порты `8080`, `9092` и `9093`.

```sh
docker compose --profile wallet-check up --build --wait
```

Профиль запускает Line, Wallet, PostgreSQL, Nginx, Swagger UI и заглушку ставок. Обычный `docker compose up` запускает только PostgreSQL. В [Swagger UI](http://localhost:8080/docs/) можно получить линию, запросить предложение и проверить баланс. Те же операции доступны из терминала.

```sh
# Снимок линии с восемью матчами
curl -fsS http://localhost:8080/api/v1/line

# Предложение на победу хозяев в первом матче
curl -fsS http://localhost:8080/api/v1/line/offers \
  -H 'Content-Type: application/json' \
  -d '{"matchId":"match-1","outcome":"HOME"}'

# Пополнение и чтение баланса
curl -fsS http://localhost:8080/api/v1/wallet/credits \
  -H 'Content-Type: application/json' \
  -H 'Idempotency-Key: demo-credit-1' \
  -d '{"amount":"10.00"}'
curl -fsS http://localhost:8080/api/v1/wallet

# Поток обновлений линии. Для выхода нажмите Ctrl+C
curl -fsSN http://localhost:8080/api/v1/line/events
```

На новом томе баланс равен `0.00`. После этого пополнения доступно `10.00`, зарезервировано `0.00`. Повтор с тем же ключом и суммой возвращает сохранённый результат без второго зачисления. Команды для проверки `Reserve`, `Capture` и `Release` через gRPC приведены в [README сервиса Wallet](services/wallet/README.md). Для остановки выполните `docker compose --profile wallet-check down`. Данные PostgreSQL сохранятся в томе.

## Как устроена линия

Два независимых генератора каждые пять секунд обновляют коэффициенты П1, Х и П2 для восьми матчей. Для каждого источника Line переводит коэффициенты в вероятности по формуле `1 / коэффициент` и нормализует их до суммы `1`. Затем усредняет вероятности двух источников с равными весами и умножает их на `1,05`. Так исходная маржа каждого источника убирается отдельно, а сумма вероятностей нашей линии до округления составляет `1,05`. Сервис снова переводит вероятности в коэффициенты и округляет их до сотых.

Рынок открыт, пока оба источника обновлялись менее 15 секунд назад. Line хранит состояние и версию линии в PostgreSQL. При каждом подключении к SSE клиент получает полный `snapshot`, затем события `match_updated` с данными изменившегося матча и новой версией. При переподключении поток снова начинается с полного актуального снимка.

## Как устроена ставка

**Предложение и кошелёк реализованы.** `POST /api/v1/line/offers` выдаёт предложение для `player-1`. Одно действующее предложение на матч и исход используется повторно, пока оно не подтверждено и укладывается в допуск по цене. При `ConfirmOffer` Line проверяет игрока и переданный коэффициент, срок действия в 60 секунд, открытость рынка и абсолютную разницу с текущим коэффициентом до `1,00` включительно. Например, предложение `2,10` можно подтвердить при текущем `3,10`, пока действует срок. Line сохраняет исходный коэффициент и результат проверки по `betId`. Идентичный повтор возвращает сохранённое решение, а подтверждённое предложение нельзя использовать с другим `betId`.

Wallet хранит условные деньги целым числом минимальных единиц. В HTTP суммы передаются десятичными строками. `Reserve` переносит сумму из доступного остатка в зарезервированный. `Capture` списывает резерв, `Release` возвращает его в доступный остаток. Wallet обновляет остатки и журнал в одной транзакции. Результаты привязаны к `betId`, поэтому повтор вызова не меняет остатки второй раз, а из двух конкурентных вызовов `Capture` и `Release` только один завершает резерв.

**Приём ставки запланирован.** `POST /api/v1/bets` должен принимать `offerId`, `odds`, `amount` и заголовок `Idempotency-Key`. Сервис Bets должен сохранять заявку в PostgreSQL, затем выполнять `ConfirmOffer` → `Reserve` → `Capture` и записывать `accepted` только после подтверждённого списания. После сбоя обработчик должен продолжать с последнего сохранённого этапа и повторять вызовы с тем же `betId`. Сейчас `POST /api/v1/bets` и `GET /api/v1/bets/{betId}` обслуживает заглушка. Эти запросы не сохраняют ставки и не меняют баланс.

## Проверки и ход работы

`make test` запускает обычные Go-тесты и тесты правил импортов фронтенда. `make test-integration` проверяет интеграцию Go-сервисов с PostgreSQL и требует Docker. В GitHub Actions также настроены `make lint`, проверка воспроизводимости сгенерированных контрактов и сборка фронтенда.
