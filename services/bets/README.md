# Bets

Bets принимает заявки `POST /api/v1/bets` для игрока `player-1`. Обработчик подтверждает предложение в Line, резервирует средства в Wallet и списывает резерв. Заявка остаётся в статусе `pending` при временной ошибке; обработчик повторяет вызов после задержки. Повтор POST с теми же параметрами и ключом возвращает тот же `betId`.

## Локальный стенд

Освободите порт 8080 от других профилей. Запустите отдельный проект:

```sh
docker compose -p bets-manual --profile bets-check up --build -d --wait
```

Откройте [Swagger UI](http://localhost:8080/docs/). Line, Wallet и POST ставки обслуживаются реальными сервисами. GET ставки возвращает сохранённый статус для игрока `player-1`. Внутренние gRPC-порты не опубликованы на хосте.

Через Swagger пополните кошелёк на `10.00`, получите линию и предложение, затем отправьте ставку на `3.00` с полученными `offerId` и `odds` и новым `Idempotency-Key`. Повторите запрос с тем же ключом: идентификатор ставки должен совпасть. Через несколько секунд баланс должен составлять `7.00` доступных и `0.00` зарезервированных. Используйте `GET /api/v1/bets/{betId}`, чтобы проверить итоговый статус ставки. При отказе предложения получите новое и используйте новый ключ.

Остановить стенд без удаления данных:

```sh
docker compose -p bets-manual --profile bets-check down
```

Для настройки обработчика доступны `BETS_LEASE`, `BETS_GRPC_DEADLINE`, `BETS_RETRY_MIN`, `BETS_RETRY_MAX`, `BETS_POLL_INTERVAL` в формате Go duration. По умолчанию используются 15 секунд, 2 секунды, 1 секунда, 30 секунд и 200 миллисекунд соответственно.

Bets использует pgx и типизированные запросы, сгенерированные sqlc из `queries/bets.sql`. Команда `make generate` обновляет сгенерированный код.
